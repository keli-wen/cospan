# AGENTS.md

## Engineering & Modularity Rules

1. **Pure ESM & Zero Runtime Dependencies**: Target Node `>=20` using `.mjs` modules only, `node:` prefixes for all built-in imports, and explicit `.mjs` extensions on relative imports. **Never add runtime `dependencies`**; tooling belongs strictly in `devDependencies` and must not enter `package.json` `"files"`.
2. **Thin Entrypoints (`src/cli.mjs`, `src/mcp/cospan-mcp.mjs`)**: Keep entry files strictly to argument/RPC dispatch and public re-exports—never accumulate state persistence, worker execution, diagnostics, or subcommand bodies inside a single file.
3. **Module Responsibilities**:
   - `src/cli-args.mjs` (flags/prompts/help), `src/job-store.mjs` (state & trajectories), `src/job-diagnostics.mjs` (bounded `observe` & recovery), `src/job-worker.mjs` (detached launch & `_worker`), `src/commands/{dispatch,lifecycle,admin}.mjs` (CLI subcommands).
   - `src/config.mjs` & `src/targets.mjs` (layered config & binary discovery), `src/contract-check.mjs` (zero-token `--help` CLI contract verification), `src/process-tree.mjs` & `src/stream-worker.mjs` (descendant PID tracking & NDJSON streaming), `src/installer-templates.mjs` & `src/installer.mjs` (host bundles), `src/drivers/{agy,codex,claude,dsh}.mjs` (target harnesses), `src/mcp/{cospan-mcp,tools}.mjs` (stdio MCP).
4. **Hard Anti-Bloat Gates**: Every `.mjs` module must stay `<= 350` effective lines (`max-lines`), functions `<= 80` lines (`max-lines-per-function`), nesting `<= 4` (`max-depth`), cyclomatic complexity `<= 15` (`complexity`), with zero circular imports (`import-x/no-cycle`).
5. **Contract Stability**: Preserve CLI flags, job exit codes (`0/2/3/4/5`), `<= 8 KiB` bounded `observe` JSON, out-of-tree `~/.cospan/trajectories/` storage, public exports (`durationToMs`, `repoRoot`, `workspaceStateDir`, `parseCliArgs`, `JOB_EXIT_CODES`, `main`), and stdio MCP behavior.
6. **Mandatory Verification Gate**: Every change must pass `npm run lint`, `npm run format:check`, and `npm test` (plus `node bin/cospan.mjs install` whenever installer templates, skills, or `src/mcp/` files change) before completion.
7. **Contribution, Issues & PR Workflow**: Follow [`CONTRIBUTING.md`](CONTRIBUTING.md) for the change-surface verification matrix (including `doctor --check`, `npm run sync:ui`, offline `tests/fakes/*` testing policy, and when to request gated `test-windows` CI). Use [`.github/ISSUE_TEMPLATE/`](.github/ISSUE_TEMPLATE/) when filing issues and fill every section of [`.github/PULL_REQUEST_TEMPLATE.md`](.github/PULL_REQUEST_TEMPLATE.md) with actual observed verification results (never fabricated checkmarks).
